# FinSage replica

Objective: replicate FinSage (Wang et al., CIKM 2025, DOI 10.1145/3746252.3761587) on FinanceBench open source, with a FastAPI + React front end, for the PI course Week 13 deliverable.
Branch: `feat/finsage-replica` · Delivery strategy: `ask-on-risk` (local repo, no remote yet) · Test runners: pytest (backend), vitest (frontend, from T6).

## Specs

- **S1 Replication target.** "Para la entrega de la semana 13 tenemos que vivecodear un paper o replicar la investigacion. Creo que podemos aplicar la de finsage". Scope narrowed by the professor: "me dice que podemos acotar a un solo documento dado a que la dataset es muy grande y por temas economicos/computacionales no podriamos hacer esto". Rebuild the FinSage pipeline in Python (FFP preprocessing, MPR retrieval with BM25, dense BGE-M3 + FAISS, metadata, HyDE and bundle expansion, DRR reranking, answer generation) over ONE FinanceBench document and its open-source questions. Document: `AMD_2022_10K`, confirmed by the user: "Sí, AMD 2022" (121 pages, 598 chunks, 7 questions mixing information extraction, numerical and logical reasoning, evidence on pages 3, 11, 42, 47, 55, 57); configurable through `FINSAGE_DOC`. The full-corpus preprocessing from T2a stays on disk as evidence that FFP scales, but retrieval, evaluation and the chatbot use only the chosen document.
- **S2 Models.** Decided: "Sí, esa combinación". Generator: `gpt-6-luna` through the OpenAI API (query rewriting, HyDE, section summaries, answers), paid from the user's US$5 credit (expected total under US$0.50 for one document). Judge: Qwen2.5-7B-Instruct running locally with Ollama on the RTX 5070, a different model family than the generator. Embeddings (BGE-M3) and reranker run locally. The LLM sits behind a `LanguageModel` port; `OPENAI_API_KEY` is read from the repo `.env`, which the user creates and is never committed (the assistant's permission settings forbid it from reading or writing `.env`).
- **S3 Visual chatbot.** "Le pregunte al profe si tengo que hacer un tipo chat bot visual y me dijo que si" and "FastAPI + React". A chat with streamed answers and page citations, a trace panel that fills live with each pipeline stage (rewritten sub-questions, per-path hits, reranked chunks, latency and cost), and a PDF viewer that opens the cited page. Conversation history feeds query rewriting, as in the FinSage repo. Demo constraint: "mi laptop tienee una gtx 1650", so the UI must also replay recorded real runs, clearly labeled as recordings. The dev-only mock backend never appears in the presentation.
- **S4 Experiments.** On the chosen document only. A: path ablation (dense, +BM25, +metadata, +HyDE, +expansion), metric = evidence-page recall. B: naive dense RAG vs FinSage replica with the same generator, judged by a model of a different family, plus cited-page hit rate. C: latency, tokens and cost per stage. Declared limitation: 7 questions cannot support statistical claims, so results are reported per question and as a qualitative comparison with the paper, not as a benchmark score.
- **S5 Architecture.** "Sip pero hagamos en una carpeta en descargas este proyecto no en la carpeta que tenemos de propuesta". The repo lives at `C:\Users\USER\Downloads\finsage-replica`, never in the Google Drive proposal folder. Packages are named after the FinSage modules (`ffp`, `retrieval`, `reranking`, `answering`), models sit behind `ports/` with implementations in `adapters/`, shared types live in `domain/`. One pipeline emits one event stream (contract in `contracts/`) consumed by the API, the evaluation and the demo recorder. FastAPI and React are adapters and never change experiment results.
- **S6 Declared limitations.** No VLM figure captioning, no DPO-trained reranker (use `bge-reranker-v2-m3`), no SFT HyDE, MinerU replaced by pymupdf4llm, coreference resolution optional by budget, Company (Lotus) dataset out of scope.
